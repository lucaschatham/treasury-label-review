# R-021: broad family coverage with a matched training budget

User explicitly resumed automated engineering. Human annotations are not a prerequisite for known-font development. R-018 added only four examples and does not establish the effect of broad training-family coverage. R-019 shows within-family ordering but cross-family score displacement. Hypothesis: broader independently sourced, balanced training families improve cross-family discrimination.

Use original 16 training families plus 48 additional OFL families, fixed before inference and disjoint from original calibration, exposed challenge and reserved families. Verify font weight 400/700, Latin heading coverage, source hashes and license. Same original rendering/packing, eight heights, two polarities and PNG/JPEG, 64 inputs per family. Reject duplicate tensors across training/evaluation. Preserve original evaluation pixels and labels.

Two arms, original 16 families versus expanded 64 families. Both start at the original ImageNet checkpoint, seed 20260923, AdamW learning rate .0001 weight decay .01, batch32, exactly 1536 optimizer steps. This is 48 original-data epochs versus 12 expanded-data epochs, equal total examples consumed. Select final checkpoint only. Original one-time calibration policy and original cohort pass criteria remain fixed. Local MPS, no service calls, maximum 900 seconds per training/evaluation arm, excluding asset preparation which has a separate 15-minute limit. Source asset download is free and bounded.

Stop before integration if any original cohort fails. Report both arms, counts, hashes, elapsed time, errors and invariants. No family exceptions, threshold search, holdout access or repeated runs after observing failures. If a candidate passes, freeze it and perform independent-family qualification and integrated timing. No font catalogue is required at inference. The proposed mechanism is broader training coverage, not R-007 reference matching or R-018 four-example exposure.
